# Job Market Research Agent Explainability

## Agent Purpose
The agent exists to analyze structured job-market datasets to provide clear, deterministic, and explainable summaries (such as salary bands and skill frequencies).

## Inputs
All inputs are expected to be structured data payloads (typically JSON/Python dicts). The agent does NOT parse raw HTML or scrape live sites.

## Decision
The agent does not "decide" things in an AI sense. It calculates them. Its decisions are purely validation-based (e.g., "Is this salary valid?"). 

## Limits
- Cannot pull real-time data.
- Cannot convert currencies automatically without external conversion factors.
- Cannot guarantee job outcomes.
- Statistics represent ONLY the dataset provided.

## Output Contract
All outputs will be structured dictionaries containing standard types (int, float, list, dict, str) representing descriptive statistics, along with a `success` boolean.

## Complete Execution Lifecycle
1. Payload received by Adapter.
2. Adapter formats payload for `AgentCore`.
3. `AgentCore` fetches the requested tool from `DynamicToolRegistry`.
4. The tool validates the payload (returning an error if invalid).
5. The tool performs standard mathematical operations.
6. The tool returns a structured response.
7. Adapter translates the response back to the caller.

## Decision/Rule Transparency (Tool-by-Tool) & Tool-by-Tool Examples

### analyze-job-listings
- **Purpose**: Count and aggregate overall listings.
- **Input**: List of job objects.
- **Output**: Aggregations by type, work mode, location.
- **Formulas**: Simple frequency counting.
- **Validation**: Rejects objects missing `job_id` or `title`.

### analyze-skill-demand
- **Purpose**: Calculate how often skills appear.
- **Input**: Job objects containing `required_skills` and `preferred_skills`.
- **Output**: Skill counts and percentages.
- **Formulas**: `percentage = (skill_count / total_jobs) * 100`
- **Validation**: Requires jobs to have list structures for skills.

### analyze-salary-data
- **Purpose**: Compute salary metrics.
- **Input**: Job objects with `salary_min`, `salary_max`, `currency`.
- **Output**: Min, max, average, median.
- **Formulas**: 
  - `average = sum(salaries) / count(salaries)`
  - `salary_midpoint = (salary_min + salary_max) / 2`
- **Validation**: Rejects negative salaries or records where `salary_min > salary_max`.

### analyze-location-demand
- **Purpose**: Group jobs by location.
- **Input**: Job objects.
- **Output**: Counts per location.
- **Formulas**: Frequency counting.
- **Validation**: Rejects missing locations safely by omitting them or logging as "unknown".

### analyze-company-demand
- **Purpose**: Evaluate the presence of employers in the dataset.
- **Input**: Job objects.
- **Output**: Job count per company.
- **Formulas**: Frequency counting.
- **Validation**: Standardizes company names (e.g., case-insensitive grouping where appropriate).

### calculate-skill-gap
- **Purpose**: Identify matches between a candidate and a job.
- **Input**: `candidate_skills` (list), `required_skills` (list), `preferred_skills` (list).
- **Output**: Match percentages and missing skills.
- **Formulas**: `match_percentage = (matched_skills / total_required_skills) * 100`
- **Validation**: Returns error if `required_skills` is empty (cannot divide by zero).

### calculate-job-market-summary
- **Purpose**: High-level market overview.
- **Input**: Job objects.
- **Output**: A comprehensive summary including all the above.
- **Formulas**: Aggregation of other tool methods.
- **Validation**: Standard dataset validations.

## Explainability of Calculated Results
Every number generated by this agent can be manually verified by reviewing the source payload and applying the documented formulas. There are no black-box weights or hidden probabilistic models involved in the core calculations.

## Provenance
- **Source**: User-supplied structured data.
- **Derived**: All metrics, percentages, medians, and averages are derived.
- **External**: N/A (Unless implemented specifically via an external Adapter).
